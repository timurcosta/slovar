# План: одна версия игры, главная без лишнего, кабинет учителя, задания от Ралины

Статус (15.10.2026): этапы 0 и 1 сделаны (одна версия, переезд с github.io, главная без лишнего),
не закоммичены; `npm run check` — 9 сценариев зелёные. Дальше этап 2.
Известное: `npm run typecheck` в `apps/api` падает на `store/ydb.ts` и `killswitch.ts` (типы `@ydbjs`),
так же и на последнем коммите — не связано с этими этапами.

Порядок: этап 0 → 1 → 2 → 3. После каждого этапа `npm run check`, просмотр скриншотов, отдельный коммит.

## Решения

- **Офлайн-версии больше нет.** Одна сборка с сервером. Без интернета игра работает как раньше
  (localStorage — основная копия), прогресс копится в `sb_dirty` и уходит на сервер, когда сеть
  появится. Настройки и задания Ралины приходят при запуске и при появлении сети.
- Открытых заданий Ралины может быть сколько угодно, записка показывает все новые.
- Хранитель задания прощает **две** ошибки.
- Награда за задание по умолчанию **150 монет**.
- Логово доступно, даже если лимит дня исчерпан (это домашка), но время и ответы идут в счётчики дня.

## Этап 0. Одна версия вместо двух

### Сборка и деплой

- Убрать `VITE_BACKEND`: `BACKEND` всегда `true` (`net/sync.ts`, `title.js`, `join.js`), из `package.json`
  убрать `dev:offline` и `build:online`; `npm run build` собирает версию с сервером в `apps/web/dist`.
- `npm run dev` как сейчас (игра + API, пароль `dev`).
- CI: job `cloud` берёт `apps/web/dist`; job `pages` выкладывает **страницу переезда** (ниже) вместо игры.
- `scripts/cloud/*`: путь `dist-online` → `dist`.

### Переезд с github.io без потери прогресса

Прогресс детей на https://timurcosta.github.io/slovar/ лежит в localStorage этого адреса, новый
адрес его не видит. Страница переезда на Pages (маленький `apps/web/moved.html`, отдельная точка сборки):

1. Читает `sb2_profile` и `sb_stats` своего адреса.
2. Если прогресс есть — показывает «Игра переехала! Твой герой {имя}, уровень N поедет с тобой» и
   кнопку «Перейти»: ведёт на адрес в Yandex Cloud с кодом сохранения в адресе (`#import=SBZ…`).
   Если прогресса нет — просто переадресует.
3. Игра на новом адресе при `#import=…`: распаковывает код (`unpackSave`, со всеми миграциями), берёт
   его, если на устройстве прогресса нет или опыта меньше, убирает `#import` из адреса. Дальше
   ученик входит по коду от Ралины, и `join` отправляет этот прогресс на сервер (там пусто).
4. Бонус: github.io остаётся постоянным адресом-ярлыком. Если шлюз пересоздадут (аварийное
   выключение → новый адрес), достаточно поменять адрес в `moved.html`.

Покрыть тестом распаковку `#import` и сценарием в `check.mjs` (старое сохранение → страница
переезда → игра на новом адресе с тем же героем).

- Надпись «Учитель включил свои слова. Сложность выбирается в разделе для учителя» →
  «Ралина выбрала слова для тебя».
- `CLAUDE.md`, `README.md`: убрать офлайн-версию и раздел учителя в игре, описать переезд.

### Работа без сети (`net/sync.ts`)

- Уже есть: `sb_dirty`, отправка раз в 30 с, при сворачивании и раз в минуту.
- Добавить: на событие `online` — отправить накопленное и один раз забрать `/me` (настройки и
  задания). Новых частых запросов не появляется.
- Первый вход по коду требует интернета (один раз). Если сети нет — понятное сообщение:
  «Для первого входа нужен интернет. Потом можно играть и без него».

### Проверка (`scripts/check.mjs`)

Все сценарии переходят на одну сборку и настоящий `apps/api` с базой в памяти:

- `new`: заставка → код → история → главная → магазин → бой.
- `veteran`, `tablet`, `laptop`, `desktop`: ученик в базе заводится заранее с прокачанным профилем,
  токен кладётся в localStorage.
- `legacy`: старое сохранение через страницу переезда.
- Новый `offline`: запросы к `/api` обрываются → игра работает, бой проходит, `sb_dirty` = true →
  сеть возвращается → прогресс дошёл до сервера.
- `online` (кабинет + ученик) остаётся и дорастает в этапах 2–3.

## Этап 2. Задания от Ралины

«Задания дня» остаются как есть. Задания Ралины — отдельная особая штука: появляются, только
если она их сделала, и открываются в выбранный день.

### Что задаёт Ралина (конструктор в кабинете)

- **Название**: «Удвоенные согласные».
- **Слова**: поиск по словарю с подсказками («бер» → берёза), кнопка «+ трудные слова ученика»,
  свои слова в формате `м(о)локо`. Хранятся строками этого формата.
- **Когда**: «сразу» или «с даты»; необязательное «до».
- **Награда**: монеты (по умолчанию 150, от 0 до 1000; подсказка «150 ≈ день игры»), галочка
  «большой сундук», галочка «именная медаль».
- **Напутствие** (на записке, необязательно) и **поздравление** (на экране победы, по умолчанию
  «{имя}, ты справился!»).

Можно запланировать неделю вперёд: понедельник — одно задание, среда — другое.

### Что видит ребёнок

1. **Записка.** Задание открылось сегодня → после заставки поверх главной всплывает тетрадный
   листок (шрифт Caveat): «Саша, новое задание от Ралины! Победи 8 монстров и Хранителя —
   получишь 150 монет, сундук и медаль», спрайты монстров, напутствие. Кнопки «В логово!» и
   «Потом». Если задание не сделано — раз в день напоминание «Монстры ещё ждут, осталось 3 из 8».
   Звук: шелест бумаги и «дзынь» (`sfx`).
2. **Карточка на главной** над «Заданиями дня»: «Задание от Ралины: Удвоенные согласные · 5 из 8».
3. **Логово.** Каждое слово — монстрик (готовый спрайт, выбирается по хэшу слова) с подписью-пропуском
   «кла__» и тремя сердечками. Верный ответ снимает сердечко, ошибка возвращает все три. Монстр
   побеждён после 3 верных подряд. Слова с ошибками выпадают чаще, одно слово не выпадает два раза
   подряд. Прогресс по монстрам сохраняется между боями: выйти можно в любой момент.
4. **Бой в логове** — обычный движок (оружие, питомцы, криты, монеты за ответы как в тренировке).
   Полоска жизней = сумма сердечек всех монстров; при ошибке она подрастает («монстр ожил»).
5. **Хранитель задания** — появляется, когда все монстры побеждены. Все слова задания по разу, без
   способностей, прощает две ошибки. На третьей уходит, а слова с ошибками снова монстрики.
6. **Победа**: поздравление Ралины, монеты, сундук, медаль. Медаль — под героем рядом с трофеями и
   на экране трофеев; остаётся, даже если Ралина удалит задание.
7. Не успел до срока «до» — задание тихо пропадает, без страшных надписей.

### Что видит Ралина

Статусы: «запланировано на чт», «открыто», «в процессе 5/8», «сделано 14 окт.», «не успел, 5/8».
Отчёт: сколько ошибок, какие слова держались дольше всех, со скольких попыток пройден Хранитель.
Всё берётся из синхронизированного профиля: без новых запросов и без поллинга.

### Как устроено

- **Контракт** (`packages/shared/src/api.ts`):
  ```ts
  interface Task {
    id: string;
    title: string;
    words: string[];
    from?: string;
    until?: string; // YYYY-MM-DD
    coins: number;
    chest?: boolean;
    medal?: boolean;
    note?: string;
    congrats?: string;
    createdAt: string;
  }
  ```
  `MeResponse.tasks: Task[]`, `Student.tasks: Task[]`.
  `POST /api/tutor/students/:id/tasks`, `DELETE /api/tutor/students/:id/tasks/:taskId`.
- **Сервер** (`apps/api/src/app.ts`): задания в `StudentRecord.tasks`; запись уже хранится JSON целиком,
  поэтому YDB и SQLite не меняются. Проверка входа: длины, число слов (≤ 40), монеты 0..1000, даты.
  Тесты в `apps/api/test/api.test.ts`.
- **Доставка** (`net/sync.ts`, `adopt`): задания кладутся в localStorage `sb_tasks` при запуске и при
  появлении сети. Открытие по дате — на устройстве (`lib/date.js today()`), работает и без сети.
- **Профиль**: новое поле `P.tasks: Record<id, TaskProgress>` — `{ title, hp: {слово: 0..3},
wrong: {слово: n}, guardTries, seen, remind, done?, medal? }`. Добавить в `freshProfile()` и
  `Profile` (`packages/shared/src/profile.ts`), тест в `apps/web/test/migrations.test.ts`.
- **Логика**: `progress/tasks.ts` (активные задания по дате, выбор слова, попадание/промах, Хранитель,
  награды). Экран логова и записка: `ui/screens/task.js`, разметка `s-task` в `index.html`,
  экран в `ui/screens.js`.
- **Бой**: `startTask(id, guardian)` в `battle/run.js`; в `round.js` две точки входа: выбор слова в
  `nextQ` и итог ответа в `resolve` (без изменений для остальных боёв); свой финал вместо `bossDown`.
  Проверку лимита дня (`limitReason`) для боёв задания пропускать.
- **Медали**: в `badgesHTML()` (`ui/screens/awards.js`) и отдельным рядом на экране трофеев.

## Баланс (по скиллу balance-change)

Формулы не меняются. Добавляется новый источник монет, которым управляет Ралина.

- **Было**: монеты за ответы, боссов, сундуки, задания дня, вход подряд; ориентир 150–250 за 15 мин.
- **Станет**: + задание. Оценка за задание из 8 слов: ~24–32 верных ответа × 3 = ~70–100 монет за
  ответы (как в тренировке, боссовых монет за логово нет) + награда Ралины 150 + сундук 3 уровня ≈ 120
  ≈ **350–370 монет**, это 1,5–2 дня обычной игры. Опыт — только за ответы.
- **Кому заметно**: новичку сильно (одно задание ≈ редкая вещь до 400); середине — ощутимый бонус;
  ветерану — мелочь. Частоту и размер решает Ралина.
- Пропадает «Наградить монетами» из раздела учителя в игре (этап 0). Если Ралине это нужно —
  задание без слов, только с наградой («Подарок от Ралины»), в этапе 2 почти бесплатно.
- Снимки `balance.test.js` не должны поменяться; если упадут — разбираться, а не обновлять.

## Проверка этапов 2–3

- Сценарий `online`: Ралина создаёт задание «сразу» и задание «с завтра» → ученик перезапускает
  игру → записка (скриншот) → карточка на главной → логово (скриншот) → бой, несколько ответов →
  прогресс ушёл на сервер → в кабинете статус «в процессе» (скриншот). Задание «с завтра» у ученика
  не видно.
- Отдельный шаг: все монстры побеждены (подготовленный `P.tasks`) → Хранитель → экран победы с
  поздравлением и медалью (скриншот).
- Кабинет: вкладки «Обзор», «Задания», «Слова и лимиты», «Вход» (скриншоты).
- `npm test`, `npm run typecheck`, `npm run lint`, затем просмотр скриншотов.
