# Репетитор: «Охотники за ошибками»

Браузерная пиксельная игра-тренажёр по русскому языку для младших школьников. Ребёнок бьёт боссов,
выбирая или вписывая пропущенную букву в словарном слове; за ответы получает монеты и опыт и тратит
их в магазине. Сейчас тема одна — словарные слова 1–4 класса. Игра — основа для расширения
**внутри неё же** (новые темы и механики), а не набор отдельных игр. Поэтому название общее
(«Охотники за ошибками», до октября 2026 — «Словарная битва») и на заставке не привязано к теме.

Запуск всегда начинается с заставки (`s-title`, `ui/screens/title.js`): живая пиксельная сцена
(`render/title.js`: небо, замок Короля Ошибок, летающие буквы; герой игрока против злодеев),
«Нажми, чтобы начать» (касание разблокирует звук и включает трек «Звёзды»), меню и ссылка
«Для учителя» (`tutor.html`). Вошедший по коду видит «С возвращением, {имя}!» и сразу играет. Остальным
после касания открывается окно «Кто играет?» (`#login`, `ui/screens/join.js`): код от учителя, «Играть как
гость» (прогресс только на устройстве, без настроек и заданий учителя; войдёт по коду — прогресс
уйдёт учителю) или ссылка в кабинет. Имя не спрашивается: ученика заводит учитель. Выбор гостя живёт до закрытия
игры (`sb_guest` в sessionStorage): устройство бывает общим, поэтому при новом запуске снова «Кто играет?», а если
на устройстве уже есть герой — «Продолжить без кода» или «Начать новым героем» (стирает героя, со второго нажатия).
На главной у героя кнопка «Похвастаться» (`ui/share.js`): картинка 1080×1350 — фон заставки, герой во весь
рост, уровень, лучшая надетая вещь с редкостью, заслуги и трофеи; «Отправить» (Web Share) или «Сохранить».
Фон на выбор (`BACKDROPS`): ночной замок с заставки и `render/scenes.js` — вулкан, космос, неон-город.
Главная (`ui/screens/home.js`) нарочно лёгкая: герой (иконка «Похвастаться» в углу), «В бой!» с переключателем
«Выбор буквы | Пишу сам ×2», ряд плиток-иконок (Башня, Магазин с «!» когда есть что купить, Достижения, Трофеи;
пиксельные SVG из `ui/icons.js`), полоска заданий дня (подробно — на экране достижений), тренировка, карта боссов
(на телефоне лентой, с 1000px сеткой). Музыка, звук, сложность слов, история и вход по коду — в окне настроек
(шестерёнка, `#prefs`). Новые кнопки на главную не добавляй — ищи им место в плитках или в настройках.

Игра делается для одного репетитора (подруги автора) и её учеников: неофициальный помощник, не сервис.
Версия одна, с сервером: ученик входит по коду от репетитора, прогресс синхронизируется, репетитор в
кабинете (`tutor.html`) видит учеников, их трудные слова и задаёт слова и лимиты. Без сети игра работает:
прогресс копится на устройстве и уходит на сервер, когда сеть появится. Первый вход по коду — только с сетью.
Отдельной офлайн-версии (с именем, разделом учителя и PIN в игре, кодом сохранения) больше нет.

  https://d5dc1pebpoct5vvkti5h.l5v6loqa.apigw.yandexcloud.net/ (кабинет — `/tutor.html`).
  `git push` в `main` → GitHub Actions (`.github/workflows/ci.yml`) гоняет проверки и, если всё зелёное,
  выкладывает (см. раздел «Облако»). Репо `timurcosta/slovar` публичный — никаких секретов, паролей и хэшей в коде.
- Старый адрес https://timurcosta.github.io/slovar/ (GitHub Pages) — страница переезда `moved.html`

  упаковывает его в код сохранения и ведёт в игру с `#import=SBZ…`; игра (`main.js`) берёт код, только

- Отвечай и пиши тексты в игре по-русски. Коммиты — короткие, по-русски, по смыслу изменения
  («Броня: полноценные доспехи поверх костюма»).

## Команды

```bash
npm i && npx playwright install chromium   # один раз
npm run dev          # игра + кабинет (localhost:5173) и API (localhost:8787), пароль репетитора "dev"
npm run build        # сборка в apps/web/dist (игра, кабинет, страница переезда)
npm run lint         # ESLint (+ typescript-eslint)
npm run format       # Prettier
npm run typecheck    # tsc
npm test             # Vitest: игра (парсер слов, снимки баланса, миграции) и API
npm run check        # сборка + сценарии в Chromium, скриншоты и localStorage в shots/
```

Перед коммитом хук (`simple-git-hooks` + `lint-staged`) сам прогоняет ESLint и Prettier по изменённым файлам.

Меню разработчика (`src/dev/panel.js`) есть только в `npm run dev`: кнопка DEV в углу или адрес с `#dev`.
Там все боссы (ярость, фильтры башни), все вещи на герое и бой-песочница с любым боссом, одной
способностью и экипировкой, с кнопками «Верно», «Крит», «Питомец», «Добить». После песочницы профиль
и статистика возвращаются как были. В сборку меню не попадает (`import.meta.env.DEV`).

`scripts/check.mjs` гоняет сборку вместе с настоящим `apps/api` (база в памяти, у каждого сценария своя).
Ученики заводятся в базе заранее (`addKid`): с профилем — уже вошли по коду на этом устройстве.
Сценарии: новый ученик (заставка → окно «Кто играет?» → код → история → главная → магазин → бой),
«прокачанный» профиль (все экраны, низ главной, «Похвастаться» — сама картинка сохраняется в
`veteran-01d-share-card.png`, вкладки магазина, башня), `legacy` — старое сохранение на прежнем адресе:
страница переезда → игра на адресе облака (подменяется локальным сервером) с тем же героем → гость → новый запуск
(снова «Кто играет?», герой цел); `small` (360×640) — прокачанный профиль на маленьком телефоне;
`offline` — запросы к API оборваны, бой идёт, `sb_dirty`, потом сеть возвращается и прогресс доходит;
`tablet` (820×1180), `laptop` (1024×768) и `desktop` (1440×900) — прокачанный профиль на больших
экранах; `victory` — победа над боссом (рассыпается на пиксели) и открытие сундука; `bossfx` — ответные
удары боссов, миньоны, пузыри, напёрстки, вторая форма Кактуса, супер-удар Меха и отбитый шар; `task` — задания Ралины:
записка, подарок, логово, монстр теряет сердечки и оживает; `task-guard` — все монстры побеждены, Хранитель, победа с
медалью и сундуком, медаль в трофеях; `online` — репетитор заводит ученика в кабинете, задаёт задания в конструкторе
(сразу и с завтра), ученик входит по коду, получает записку и бьёт монстров, в кабинете статус «в процессе»; прогресс
и настройки репетитора ходят через API. При отладке можно гонять часть: `ONLY=task,online npm run check`. Время и `Math.random` зафиксированы, полоска таймера и
случайный код ученика замаскированы, поэтому
прогоны **детерминированы** и их можно сравнивать побайтно. Скрипт падает при ошибках в консоли.

После любой правки: `npm run check`, затем посмотреть скриншоты затронутых экранов (их можно
открывать через Read). Для рефакторинга без изменения поведения сравни с прошлой версией:

```bash
git worktree add /tmp/base HEAD && (cd /tmp/base && npm ci && npm run build)
node scripts/check.mjs /tmp/base/apps/web/dist/index.html /tmp/shots-base
npm run check
for f in /tmp/shots-base/*; do cmp -s "$f" "shots/$(basename $f)" || echo "DIFF $(basename $f)"; done
```

## Устройство

Монорепо на npm workspaces:

- `apps/web` — игра (`index.html`, вход `src/main.js`) и кабинет репетитора (`tutor.html`, вход `src/tutor/main.ts`).
- `apps/api` — сервер на Hono (TypeScript, Node 24 запускает его без сборки).
- `packages/shared` — общие типы: формат сохранений (`profile.ts`) и контракт API (`api.ts`).
  **Только типы** (`import type`): Node не снимает типы с файлов в `node_modules`.

### apps/web

Vite, ES-модули, без фреймворка. `index.html` — разметка экранов (`<section id="s-...">`).
Слои снизу вверх; модуль может импортировать свой слой и те, что ниже:

| Папка       | Что внутри                                                                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `lib/`      | Утилиты без знаний об игре: `$`, `esc`, случайность, даты, склонения                                                                               |
| `content/`  | Только данные и чистые функции: боссы, предметы, костюмы, внешность, питомцы, ауры, трофеи, спрайты                                                |
| `render/`   | Отрисовка на canvas: `drawSprite`, `drawBoss`, `drawHero`                                                                                          |
| `topics/`   | Темы заданий. `topics/words/`: списки слов, разбор формата, наборы слов для боя                                                                    |
| `state/`    | Сохраняемые данные (TypeScript): `types.ts`, `storage.ts`, `migrations.ts`, `profile.ts` (`P`, `save()`), `settings.ts`, `stats.ts`, `savecode.ts` |
| `progress/` | Уровни, `gear()`, награды и сундуки, задания дня, достижения, трофеи, открытия, лимиты дня                                                         |
| `audio/`    | `AudioContext`, эффекты `sfx.*`, музыка                                                                                                            |
| `battle/`   | Забег `G` (`run.js`), раунд и ответы (`round.js`), сложность, эффекты, HUD                                                                         |
| `net/`      | `http.ts` (запросы к `/api`), `sync.ts` (вход по коду, синхронизация прогресса и настроек)                                                         |
| `ui/`       | Экраны (`ui/screens/*`), переключение экранов, тосты, иконки, конфетти, анимация героя                                                             |

Известные связи «вверх», которые стоит распутать при случае: `progress/` пишет в DOM (тосты, монеты
в шапке) и смотрит в текущий бой `G`; `topics/words/pools.js` берёт тренировочный набор из `G`;
`render/hero.js` берёт внешность игрока из профиля.

Кабинет (`src/tutor/`: `main.ts` — вход, пароль, маршруты; `list.ts`, `student.ts` — вкладки ученика `#/s/:id[/tasks|words|login]`,
`tasks.ts` — конструктор и отчёт, `common.ts`) импортирует только чистые модули (`lib`, `content`, `progress/levels`,
`progress/taskrules`, `topics/words/parse`, `net/http`). Модули `state/*` при загрузке читают и сохраняют профиль игрока —
в кабинет их не тянуть.

### Правила модулей

- Привязку `let` можно переприсвоить только в её модуле (ES-модули). Для этого есть сеттеры:
  `resetProfile()`, `setStats()`, `setCustomRaw()`. Менять поля объекта (`P.coins += n`) можно откуда угодно.
- Код верхнего уровня, который выполняется при загрузке, не должен трогать то, что объявлено в
  модулях, загружаемых позже (циклические импорты). Безопасно всё, что внутри функций и обработчиков.
  Если тест или сборка падает с `undefined`/`ReferenceError` при загрузке — ищи цикл.
- `content/` и `lib/` не импортируют ничего выше себя — это держит их тестируемыми.
- Новые модули в `state/` и всё, что пойдёт на сервер, пиши на TypeScript. Остальное можно
  переводить постепенно (`allowJs`, импорты `.ts` пишутся с расширением).

### Состояние

- `P` — профиль игрока (сохраняется целиком), `G` — текущий забег (`null` вне боя), `settings`,
  `stats` — `{слово: {right, wrong}}`. Типы — в `state/types.ts`.
- Любое изменение `P` → `save()`. Экраны перерисовываются явно (`renderHome()`, `renderShop()`, `renderHUD()`).

## Сервер и синхронизация

API описан типами в `packages/shared/src/api.ts`, реализация — `apps/api/src/app.ts` (`createApp`).
Он не знает, где запущен и какая база: хранилище за интерфейсом `Store` (`apps/api/src/store/`):
`MemoryStore` (тесты, проверка), `SqliteStore` (разработка, файл `apps/api/.data/dev.sqlite`),
YDB — при развёртывании в Yandex Cloud.

- Кабинет один, паролей два. Пароль администратора (владелец, отладка) — хэш в `TUTOR_PASSWORD_HASH`
  (`npm run cloud:password`, локально `npm run hash-password -w @repetitor/api -- 'пароль'`), работает всегда.
  Учитель первый раз входит им и в кабинете («Пароль», `#/account`) задаёт свой: его хэш лежит в базе
  (`Store.getTutor/putTutor`, в YDB таблица `tutors` создаётся сама при первом обращении), `POST /api/tutor/password`.
  В токене кабинета `who: admin | tutor`. Токены подписываются `AUTH_SECRET`.
  Ни то, ни другое не коммитить: репо публичное. Хук перед коммитом и CI запускают
  `scripts/no-secrets.mjs` — он ищет токены Yandex Cloud, хэши паролей, закрытые ключи. Секреты живут
  только в настройках функции в облаке, в GitHub Secrets и в `.env` (он в `.gitignore`).
- Ученик входит по 6-значному коду. Токен ученика бессрочный, но «Выдать новый код» отключает старые входы.
- Синхронизация (`net/sync.ts`): после `save()` прогресс уходит на сервер не чаще раза в 30 с (и сразу при сворачивании игры) с `baseRev`.
  Если на сервере уже другой `rev` (играли на двух устройствах) — сервер отвечает 409, и побеждает
  версия с бо́льшим опытом. Без сети всё копится локально (`sb_dirty`) и уходит позже.
- Настройки и задания репетитора (режим слов, свои слова, лимиты; `MeResponse.tasks` → `sb_tasks`) ученик получает
  при запуске игры и когда появляется сеть (событие `online`).
- Данные детей — минимум: имя, прогресс, статистика слов. Почту, телефоны и т. п. не собирать.

## Облако (Yandex Cloud)

Всё в одном каталоге, создаётся и обновляется скриптом `scripts/cloud/deploy.mjs` (`npm run cloud:deploy`,
повторный запуск безопасен). Нужны вход в `yc` (`yc init`) и `.env` в корне (в `.gitignore`):
`TUTOR_PASSWORD_HASH` (задаёт владелец через `npm run cloud:password`, пароль нигде не хранится) и
`AUTH_SECRET` (скрипт генерирует сам). Без пароля кабинет закрыт случайным паролем.

| Ресурс                          | Что                                                                                              | Ограничения против расходов                           |
| ------------------------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------- |
| YDB serverless `repetitor`      | таблица `students` (ученик целиком JSON-строкой)                                                 | 1 ГБ, 10 RU/s, без платной зарезервированной мощности |
| Бакет `repetitor-web-<каталог>` | сборка `dist`                                                                                    | приватный, 1 ГБ; HTML `no-cache`, ассеты на год       |
| Функция `repetitor-api`         | `apps/api/src/cloud.ts`, собирается esbuild в `apps/api/dist`                                    | Node 22, 256 МБ, 10 с, не больше 2 копий на зону      |
| API Gateway `repetitor`         | `/api/*` → функция, остальное → файлы из бакета                                                  | —                                                     |
| Сервисные аккаунты              | `repetitor-api`: только `ydb.editor` на базе; `repetitor-gateway`: вызов функции и чтение бакета | —                                                     |

- Функция берёт токен для YDB из контекста вызова (сервисный аккаунт), ключей нет.
- Бесплатный уровень: 100 тыс. запросов к шлюзу и 1 млн вызовов функций в месяц. Поэтому синхронизация
  не чаще раза в 30 с. Не добавляй частых запросов к API (поллинг и т. п.).
- `npm run cloud:test-ydb` — тесты API против настоящей YDB во временной таблице.
- **Выкладка из GitHub**: пуш в `main` → job `cloud` в CI (`scripts/cloud/ci-deploy.mjs`) обновляет код
  функции и файлы игры. Входит без ключей (федерация `github-actions` → сервисный аккаунт
  `repetitor-deployer`, только ветка `main` этого репо: subject `repo:timurcosta@29523821/slovar@1414524500:ref:refs/heads/main` — у репо включены неизменяемые subject с id, скрипт берёт формат из GitHub; при переименовании репо —
  перезапустить `npm run cloud:deploy`). Секреты новая версия берёт у текущей. Шлюз, базу, роли и пароль
  меняет только `npm run cloud:deploy` с компьютера владельца.
- **Аварийное выключение**: триггер `repetitor-budget-stop` на бюджет «Страховка» (100 ₽/мес) вызывает
  функцию `repetitor-killswitch` (`apps/api/src/killswitch.ts`). На 100% она удаляет API Gateway — запросы
  перестают тарифицироваться, игра у детей уходит в офлайн. Вернуть: `npm run cloud:deploy`; у шлюза
  будет **новый адрес**, ученикам нужно будет войти по коду заново (прогресс на сервере цел).
- В бюджете биллинга стоит уведомление на 50 и 100 ₽ в месяц.

## Формат слов и новые темы

Слово записывается с вариантами в скобках: `б(е/и)рёза` — верно `е`, ловушка `и`. Если ловушка не
указана, её подбирает `autoWrong` (`о↔а`, `е↔и`, удвоенная → одинарная: `а(лл)ея`, заглавная →
строчная). В слове может быть несколько мест; в бою спрашивается одно, в режиме «вписать» — всё слово.
Учитель может задать свои слова тем же форматом (`settings.words === "custom"`).

Новая тема — ещё одна папка в `topics/`, а боссы, награды, магазин и прогресс остаются общими.
Вопрос сейчас — «слово с местами для выбора» (`WordEntry` в `topics/words/parse.ts`), и формат уже
подходит для многих тем. Если тема в него не ложится, сначала расширь модель вопроса в
`battle/round.js` (`nextQ`/`resolve`), не ломая словарные слова.

## drawHero: размеры холста

`drawHero(cv, eq, wrap, fr)` (`render/hero.js`) рисует героя попиксельно на маленький canvas, а CSS растягивает его
(`image-rendering: pixelated`). Размеры заданы в начале функции:

- фигура `W=30 × H=27`, сверху запас `TOP=4` (поднятое оружие, «дыхание»), слева полоса `PETW=10` под питомца;
- холст `CW = W+2+PETW = 42`, `CH = H+1+TOP = 32`; по краям 1px запаса, чтобы не резался контур;
- рисование идёт в локальных координатах со сдвигом `(LX=11, TOP)`; тело героя от `ox=6, oy=4`;
- `M(...)` рисует зеркальную пару относительно оси `x = ox+10`; `R` — прямоугольник, `P` — пиксель;
- питомец рисуется левее, `x - 10`, и стоит на нижней линии `H`; ауры — в координатах 0..29 × 0..26;
- `outlined(fn)` обводит группу пикселей тёмным контуром, в конце обводится вся фигура;
- `fr` — номер кадра анимации (крылья, дыхание, моргание, ауры, питомцы), тикает каждые 170 мс.
- ручное оружие наклонено вперёд: рисуется прямо на отдельном слое, потом строки сдвигаются лесенкой
  от руки (2:1, длинным клинкам круче, чтобы конец не вылез за холст); пушки из `LEVEL_WEAPONS` ровно.
  Новое оружие рисуй вертикально, наклон сделается сам.
- в бою питомец — отдельный холст `#pet-cv` (`drawPet`, тот же масштаб): героя там рисует `drawFighters()`
  без питомца, и питомец атакует сам, не уезжая с героем при замахе. На остальных экранах питомец
  по-прежнему внутри `drawHero`. Хореография с питомцем ближнего боя (`battle/effects.js`): герой
  подбегает и бьёт, ждёт у босса, питомец подбегает и бьёт, обратно оба вместе; огонь, лазер и
  снаряды летят из пасти по спрайту (`petMouth`).

Если что-то не помещается — увеличивай запасы `TOP`/`PETW`, не обрезай. Один и тот же `drawHero`
рисует героя на главной, в бою, в магазине (примерка), на экране конца и в подарках, проверяй все места.

## Профиль и миграции (осторожно)

Ключи localStorage: `sb2_profile` (профиль `P`), `sb_settings`, `sb_stats`, `sb_custom`; вход и синхронизация —
`sb_token`, `sb_tutor_name`, `sb_rev`, `sb_dirty` (`sb_guest` теперь в sessionStorage); `sb_hero` — самый старый формат, переносится при первом
запуске; `sb_pin` (хэш PIN старого раздела учителя) больше не читается.
У детей реальный прогресс, потерять его нельзя.

Все миграции — в чистой функции `migrateProfile(stored, legacyHero)` (`state/migrations.ts`):
без localStorage и DOM, покрыта тестами, повторный прогон ничего не меняет. Её же должен
использовать сервер при приёме сохранений.

- Слияние со стартовым профилем **поверхностное**. Новое поле верхнего уровня добавляй в
  `freshProfile()` и в `Profile` (`state/types.ts`). Вложенные объекты (`tot`, `up`, `equip`)
  доливаются отдельно — новое вложенное поле добавляй и туда.
- Предметы хранятся по `id` в `P.owned` и `P.equip`. **Не переименовывай и не удаляй id.** Если
  нужно убрать предмет — пиши миграцию с компенсацией (как `oscar` → `cat` + 2500 монет).
  Экипировка с неизвестным id сбрасывается на `DEFAULT_EQUIP` раньше остальных миграций (поэтому
  у старых сохранений с Оскаром на питомце он снимается, а не превращается в кота — известная особенность).
- `P.beaten` и `P.unlocked` — **индексы** в `BOSSES`. Вставка босса в середину `CAMPAIGN` сдвигает
  индексы: нужна миграция по именам и новая версия `rv` (сейчас 3: список прошлой кампании `CAMPAIGN_V2`
  в `state/migrations.ts`, старый индекс → имя → нынешний индекс). В коде боссов ищи по имени (`bossIdx`),
  а не по номеру.
- Смена формулы опыта — новая версия `xpv` с подъёмом `xp`, чтобы уровень игрока не упал.
- Код сохранения (`SBZ…`/`SBJ…`, `state/savecode.ts`) — это сжатый JSON `{v, p: P, s: stats}` (`SaveData`).
  Экрана с кодом в игре больше нет, но им переносится прогресс со старого адреса (`#import=`), и там
  могут быть сохранения любой давности: они проходят те же миграции, поэтому миграции не удаляй.
- Новую миграцию покрывай тестом в `apps/web/test/` и, если она видна в игре, сценарием `legacy` в `scripts/check.mjs`.

## Экономика и баланс

**Не меняй баланс без явной просьбы.** Если правка задевает цифры (цены, награды, урон, жизни
боссов, уровни), сначала напиши, что было и что станет, и для какого игрока это заметно.
Ориентир: 15 минут игры в день дают примерно 150–250 монет. Цифры закреплены снимками в
`apps/web/test/balance.test.js`: упавший снимок значит, что баланс изменился. Обновляй снимок
(`npx vitest -u`) только если изменение задумано.

- Уровни: `lvlXP(n) = 50·n·(n−1) + n³`, максимум 50. За уровень: `60·l` монет + сундук 1 уровня без вещи.
- Верный ответ: монеты `(крит ? 6 : 3) · mult`, опыт `(крит ? 15 : 10) · mult`,
  `mult = (вписать слово ? 2 : 1) · diffMul`, `diffMul`: смешанные слова 1.5, сложные 2, иначе 1.
- `addCoins` умножает на `gear().coinMul` (броня, питомец, «Богатство» +10% за уровень), если не
  передан `useMul=false`; `addXP` умножает на `gear().xpMul` (шлем).
- Победа над боссом: монеты `30 + lvl·9` (в башне `30 + этаж·9`), опыт `30 + lvl·5` (башня `30 + этаж·4`),
  оба × `diffMul`; плюс сундук. Каждый 10-й этаж башни: `300 + этаж·20`.
- Сундук уровня t: `25 + 18t + rand(25 + 18t)` монет; шанс вещи `0.08 + 0.04t` (только вещи дешевле 1500,
  открытые по уровню).
- Задания дня: 3 штуки, награда `90 + 45·i` за сложность i; все три — сундук 3 уровня.
  Вход подряд: `30 · min(дней, 7)`.
- Боссы кампании: ступень `lvl = i·27 / индекс Короля` (Король всегда 27, Тень Короля после него чуть выше),
  жизни `90 + 20·lvl`, время `max(5, 13 − 0.35·lvl)` с. Башня: жизни `110 + 22f + 0.35f²`,
  время `max(4.5, 12 − 0.3f)`, способности добавляются с 3, 6 и 15 этажа.
  Сложность: смешанные ×1.3 жизни, ×0.8 времени, +1 способность; сложные ×1.7, ×0.62, +2.
- Урон, жизни боссов и очки на экране показываются ×10 (`DMG_SHOW` в `content/rules.ts`, в текстах вещей тоже ×10),
  считается всё в мелких числах. Числа урона в текстах вещей пиши уже ×10.
- Бой: урон оружия + питомец (`dmgPlus`: котик 2, робопёс 3, мини-дракон 3, дрон 3, танк 4, дракончик
  Тьмы 4, звёздный 5, феникс 10; свою долю, включая крит, питомец наносит сам своей атакой) + «Сила»; вписанное слово ×1.5; крит с серии 3 (×2, у некоторых питомцев
  больше); каждые 5 подряд +1 сердце. Сердца `5 + броня + «Живучесть» (+2 на лёгких словах) + лепёшка`.
- Прокачка: цена `base · k^n`, округление до 10. Лестница редкости по цене: обычный < 400,
  редкий < 1500, эпик < 5000, легенда < 15000, миф < 40000, ультра от 40000.

## Задания от Ралины

Отдельно от «Заданий дня» (`progress/daily.js`, их не смешивать): Ралина в кабинете задаёт ученику задание —
слова, дата «с»/«до», награда (монеты 0..1000, сундук 3 уровня, именная медаль), напутствие и поздравление.
Хранятся в записи ученика на сервере (`Task` в `api.ts`, `StudentRecord.tasks`; `POST/PUT/DELETE
/api/tutor/students/:id/tasks`), гостям не приходят. Открываются по дате на устройстве, прогресс — `P.tasks[id]`
(`TaskProgress` в `profile.ts`), с ним кабинет показывает статус и отчёт без лишних запросов.

- Правила без DOM — `progress/taskrules.ts` (тесты `test/tasks.test.ts`): каждое слово — монстр с 3 сердечками, верный
  ответ снимает одно, ошибка возвращает все; слова с ошибками выпадают чаще, одно слово не два раза подряд. Когда все
  побеждены — Хранитель: все слова по разу, прощает 2 ошибки, на третьей уходит, и слова с ошибками снова монстры.
- Игра: `progress/tasks.ts` (список, записка, награда, медали), `battle/task.js` (логово и Хранитель на обычном движке:
  `G.kind === "task"`, ветки в `nextQ`/`resolve`, жизни — сердечки × `TASK_U`, свой финал вместо `bossDown`),
  `ui/screens/task.js` (записка `#task-note` раз в день, карточка `#home-tasks` над «В бой!» — единственное исключение
  из «без новых кнопок на главной», экран логова `s-task`). Монеты за ответы — как в тренировке; лимит дня бои по
  заданию не останавливает, но время и ответы в счётчики идут. Задание без слов — подарок: забирается с записки.
- Медаль остаётся, даже если задание удалить (название хранится в `P.tasks[id].title`): под героем и на экране трофеев.

## Прочее

- Лимиты на день (минуты, новые слова, ответы, бои, ошибки) задаёт учитель в кабинете: при достижении
  бой останавливается, прогресс сохраняется.
- Музыка и звуки синтезируются в WebAudio, внешних файлов нет. Шрифты — Google Fonts. В бою играют
  боевые треки: каждый новый бой берёт следующий из `TRACK_ORDER` (кнопка «Музыка» листает вручную),
  у боссов с формами на сложных словах (`FORMS`, пул `b`) — «Чемпион», на остальных экранах — спокойные по
  `SCREEN_MUSIC` в `audio/music.js`: `show()` сам меняет трек при переходе между экранами.
- Подлянки боссов (`AB` в `content/bosses.js`, срабатывают в `nextQ`): у каждой есть ответ руками, и он работает
  пальцем, мышкой и с клавиатуры. Облако и двойки сбиваются нажатием, кляксы стираются, лёд и паутина рвутся
  нажатиями или клавишами, часы ловятся, крошечное и перемешанное слово возвращается нажатием, щиты панциря
  разбиваются ударами. Подлянка без ответа или без видимого эффекта — не подлянка. Никогда не показывай слово с
  ошибкой (ни «подсказкой», ни зеркально). Миньоны и пузыри лопаются нажатием (на кнопке — нажатием кнопки
  или клавишей 1/2, на поле ввода — любой клавишей), стаканчики напёрстков поднимаются нажатием, заряд
  супер-удара сбивают 3 верных подряд, а летящий шар отбивается нажатием или любой клавишей (`trickKey`).
- Формы боссов (`FORMS`, у стража каждого 10-го этажа башни — `forms` в `towerBoss`): ниже порога жизней
  босс превращается (`changeForm` в `round.js`: пауза, вспышка, новый спрайт/палитра, имя, подлянка, атака).
- Ответный удар на ошибку — `bossAttack()` в `battle/effects.js` по `ATTACK[палитра]` (во второй форме
  `G.boss.atk`): клякса, штамп, иглы, луч, заклинание, кость, сюрикены, снежок, язык, самолётики, огонь,
  ядро, ракета, молния, укус. Сердце снимается в момент попадания; щит героя отбивает, уклон — герой
  подпрыгивает. Победа — босс рассыпается на свои пиксели (`vfx.shatter`).
- Атаки оружием — `fx()` в `battle/effects.js`: ближний бой — замах настоящим оружием, дальний и магия —
  пиксельный движок `battle/vfx.js` (canvas поверх арены, пиксель эффекта = пиксель героя: снаряды,
  шлейфы, взрывы, лучи, спираль рельсы). `fx()` возвращает момент попадания — тогда показывается урон.
- Размеры на арене: ширина героя `--hw` (доля ширины сцены), босс — от неё: `drawBoss` ставит `--bk`,
  пиксель босса в `BOSS_PX` раз крупнее пикселя героя. Так боссы одного масштаба и крупнее героя.
- Тексты для детей: дружелюбно, без пугающих формулировок, обращение по имени (`P.name`).
- Магазин (до октября 2026 — «Гардероб», в коде по-прежнему `shop`) — «Лавка Котофея» (вывеска на навесе).
  Торгует Котофей (`content/merchant.js`: спрайт, палитра, реплики; `keeperSay`/`drawKeeper` в `ui/screens/shop.js`):
  чёрный котик-волшебник в колпаке и звёздном плаще, с кружкой какао. Сонно моргает, хвост качается, над кружкой
  вьётся пар (тик анимации героя). Шутит на всё: вход (богатому и бедному по-разному), вкладки, примерку по редкости и
  цене, «Надеть», покупку, кузницу, внешность, серию поглаживаний (5/10/20); через 25 с без дела засыпает. Музыка
  магазина — кантри-трек «Лавка» (`TRACKS.shop`).
- Окно поверх боя (`#boss-over`: знакомство с боссом, победа, сундук) лежит в одной ячейке сетки с `.arena-in`:
  длинное окно растит арену, а не прячется за прокруткой внутри неё. Кнопки «Готово»/«Назад» под длинными
  списками (магазин, достижения, трофеи, итоги боя) — в `.backbar`, она прилипает к низу экрана.
- Учитывай телефоны: основные проверки идут в окне 390×844, есть сенсорный режим (`TOUCH`) и экранная
  клавиатура. Вёрстка мобильная по умолчанию; от 720px шире лист и крупнее бой, от 1000px главная и
  магазин в две колонки (`.cols > .col`, на телефоне обёртки «прозрачные»), а в ландшафте бой в две
  колонки: арена слева, слово и ответы справа. Ширина листа — `--sheet`.
